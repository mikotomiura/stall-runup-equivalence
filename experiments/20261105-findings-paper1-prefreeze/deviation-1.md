# Deviation 1 / 逸脱 1 (2026-11-06)

## English (governing)

- What happened: stage 2 of the holdout run (start record: https://osf.io/hfvy7, start.json SHA-256 53ef6f9c5531b706c53d11f0f3b6207cbf59045374f9c7a55f842942d3e820dd) stopped at the conversion step, before any statistic was computed. The registered check "the number of writers read by the conversion equals the number of writers in the holdout list" (P3, Appendix E) failed: 145 / 146.
- Cause: one holdout writer has a single row in the raw data (`File.Edit` with `X-Checkpoint`) and no key press or other event that creates an assignment unit, so the conversion reads no unit for that writer. The check assumed that every listed writer has such rows. This writer has no key presses and would be excluded in any case (observation under 10 minutes, Appendix A2). No decision value, AUC, or per-writer value of the holdout was computed or seen; only the row count and event kinds of that one writer were inspected to find the cause.
- Change: the check is replaced by `scripts/check_holdout_writers.py`, which requires (1) every writer read into the intermediate is in the holdout list, and (2) every holdout writer not read has zero rows that create units under the same mapping as the conversion (`map_2019` of `build_cs1.py`), and (3) read + not read = 146. It writes the counts (no IDs) to `results_holdout/holdout_writers_check.json`. Negative controls: dropping one read writer from a copy of the intermediate list, or adding a writer outside the holdout, both make the check fail. Nothing else in the rules, the statistics, or the scripts changed, apart from adding this note and the new checker to the manifest (`make-manifest.sh`).
- Procedure: the change was made at the researcher's decision after the stop was reported (P11, Appendix E). The new manifest is registered in a separate OSF registration of the same project together with this note and the frozen files. The run is restarted from stage 1 with the reason given (the previous outputs are moved aside and committed), the new start record is registered, and only then stage 2 is run. The decision is taken from the first completed run, which will be this restarted run. The paper reports the interrupted run, this deviation, and the order of the OSF registrations.

## 日本語（訳）

- 起きたこと: 取り置きの手順の 2 段目（開始の記録 https://osf.io/hfvy7）が、変換の段で、どの値も計算する前に止まった。登録した照合「変換で読んだ書き手の数が取り置きの一覧の人数と同じ」（P3・付録 E）が 145 / 146 で通らなかった。
- 原因: 取り置きの 1 人は生の記録が 1 行だけ（`File.Edit` の `X-Checkpoint`）で、課題を作る押下も出来事も無いので、変換はこの書き手の課題を 1 つも読まない。照合は一覧の全員にそうした行があると決めつけていた。この書き手は押下が無く、どのみち除かれる（観測 10 分未満・付録 A2）。判定の値・AUC・取り置きの書き手ごとの値は計算も閲覧もしていない。原因を調べるために見たのは、その 1 人の行の数と出来事の種類だけである。
- 変えたこと: 照合を `scripts/check_holdout_writers.py` に替えた。(1) 中間に読んだ書き手は全員取り置きにいる、(2) 読まれなかった取り置きの書き手は、変換と同じ写像（`build_cs1.py` の `map_2019`）で課題を作る行が 0 件、(3) 読んだ数 + 読まれなかった数 = 146 を求め、数だけ（ID なし）を `results_holdout/holdout_writers_check.json` に書く。陰性対照: 中間の一覧から読んだ書き手を 1 人消した写しと、取り置きの外の書き手を足した写しで、どちらも止まる。規則・推定量・ほかのスクリプトは変えていない（manifest にこの記録と新しい照合を足したことを除く）。
- 手順: 止まったことを研究者に報告し、研究者の判断で直した（P11・付録 E）。新しい manifest は、この記録と凍結のファイルと一緒に、同じプロジェクトの別の OSF の登録にする。理由を付けて 1 段目からやり直し（前の走りの出力は退避してコミットする）、新しい開始の記録を登録してから 2 段目を回す。判定はこのやり直しの走り（最初の完走）の値を使う。論文では、中断した走り・この逸脱・OSF の登録の順を報告する。
