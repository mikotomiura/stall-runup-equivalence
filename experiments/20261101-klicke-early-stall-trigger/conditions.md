## K3 変換（1 本の CSV → GSE の NDJSON）

- 読み込みは照合論文の検査 1・2 に合わせる: utf-8 で読めなければ cp1252。`DownEvent` のバックスラッシュつきの 2 字（`\"`・`\\`）を戻す。使う列は `DownTime`・`UpTime`・`DownEvent` だけ（`TextChange`・`Activity`・`CursorPosition` は読まない）。
- 1 行を 1 回の押下とし、押下 `DownTime`・離し `UpTime`（記録の実時刻・合成しない）の key 行 2 つにする。時刻は ms で、全セッションに同じ定数（1,700,000,000,000）を足す。
- マウスの出来事（`DownEvent` が `Leftclick`・`Rightclick`・`Middleclick` など、名前に `click` を含むもの）は key 行にしない。
- キーの種類（`DownEvent` の値 → GSE の category）:
  - 英字 1 字 → `alphabetic`・数字 1 字 → `numeric`・`Space` → `space`・`Enter` → `enter`・`Tab` → `tab`
  - `.` `,` → `sentence_punctuation`・それ以外の ASCII の記号 1 字 → `punctuation`
  - `Backspace` → `backspace`・`Delete` → `delete`
  - `Shift`・`Control`・`Alt`・`Meta`・`CapsLock` など修飾 → `modifier`
  - 矢印・`Home`・`End`・`PageUp`・`PageDown` → `navigation`・`Escape` → `escape`・`F1`〜`F24` → `function`
  - それ以外（1 字の非 ASCII を含む）→ `other`
  - 実データの `DownEvent` の値の種類と数（値ごとの件数だけ）を `results/key_vocabulary.json` に出し、`other` に落ちた値を報告する。対応表は件数を見る前に固定し、見た後に変えるなら逸脱として書く。
- 押下が 200 未満のセッションは除く（θ の 100 間隔が貯まらない・数を報告する）。
- replay: `gse-replay <ndjson>`（既定の FeatSnapshot）→ `add_feat.py`（項目 1 の道具）→ `gse-replay <withfeat> --features`（停滞の始まり・極は既定の baseline）。1 人 1 セッションなので書き手ごとにつながない。

## K4 共通の定義

- 文字の入力: category が alphabetic・numeric・punctuation・sentence_punctuation・space・enter・tab の押下（案 A の S3 と同じ）。
- 休止: 文字の入力 u から次の文字の入力 u⁺ まで（無ければセッションの最後の押下まで）。
- θ(t): 時刻 t 以前の押下どうしの隣接の間隔（観測区間の中だけ）の 0.99 分位（nearest-rank）。間隔が 100 未満なら未定義（GSE の `theta_at` と同じ規則・`p1-episode.json`）。Python で計算し、replay の onset 行の `theta_person_ms` と全件一致することを確かめる（1 件でも違えば止める）。
- 停滞: replay の `--features` が立てた onset（`s_ms`・`t0_ms`）。
- 条件 A のタイムライン（時計 B に使う）: GSE の規則（30 秒の窓の正味の産出が 1 未満）を Python で再現する。再現した確定の onset の組（s, t0）が replay と全件一致することを確かめる（違えば止める）。
- 適格な時間: θ が定義された最初の時刻から、セッションの最後の押下まで。1 時間あたりの頻度はこの時間で割る。適格な時間が 10 分未満の書き手は主の集計から除く（数を報告する）。

## K5 主: 止まりの初期の発火（k = 0.5・0.75）

- 時計 A（最後の文字から・主）: 休止 [u, u⁺) で、u⁺ − u > k·θ(u) かつ θ(u) が定義されていれば、時刻 f = u + k·θ(u) に 1 回発火する。
- 時計 B（停滞の時計・副）: 条件 A の立ち上がり s ごとに、θ(s) が定義され、条件 A が s から s + k·θ(s) まで続いていれば、f = s + k·θ(s) に 1 回発火する。
- 今の契機（比べる相手）: `invitation.rs` の契機の部分だけを再現する: FeatSnapshot の `p_stuck ≥ 0.60` が 30 秒続いた時刻 f に発火し、直前の押下からの経過が 180 秒以上（離席候補）なら出さない。区間は `p_stuck < 0.60` が 60 秒続くか離席候補に入ると終わり、1 区間に 1 回。閉じた後の 30 分・1 日の上限・本人の選ぶ時間帯は入れない（契機の頻度を比べるため・政策の上限は別）。

- 出すもの（書き手ごと → 書き手の分布）:

  2. 停滞に至る割合: 全員の発火を合わせた比（至った発火 / 発火）と、書き手で再標本化した 95% 区間。発火が 5 回以上の書き手での書き手ごとの割合の中央値も併記する。
  3. 停滞の取りこぼし（参考）: 停滞のうち、t0 より前に同じ休止で発火があった割合（3 つの契機）。
  4. 発火から t0 までの時間（停滞に至った発火）の中央値と四分位。
